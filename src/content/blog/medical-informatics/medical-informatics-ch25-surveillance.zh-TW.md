# 1. 監測的定義與三項目的

監測把資料轉成可用資訊，再交給需要決策與執行的人。==只收資料或做漂亮圖表，還沒有完成公共衛生監測的目的==。

| 目的                     | 內容                                   | 例子                             |
| ------------------------ | -------------------------------------- | -------------------------------- |
| 建立疾病自然史及長期趨勢 | 了解人、時、地分布、危險因子與傳播方式 | 找出高風險族群及季節變化         |
| 偵測即時疫情             | 比較背景值、閾值及人時地聚集           | 發現異常病例增加，啟動查證與調查 |
| 制定與評估政策           | 用資料支持措施並持續追蹤               | 評估疫苗政策或防治措施後的變化   |

建置前先決定==監測什麼、監測誰、多常蒐集／通報==，另需安全、方便且可持續的通報管道。

# 2. 指標式與事件式監測

| 比較     | 指標式 IBS                         | 事件式 EBS                         |
| -------- | ---------------------------------- | ---------------------------------- |
| 核心     | 按既定定義與格式蒐集資料           | 發現可能有公共衛生意義的事件訊號   |
| 常見資料 | 病例、診斷碼、檢驗、死亡與就醫統計 | 新聞、社群及網路事件資訊           |
| 資料型態 | 以結構化、可比較數據為主           | 以非結構化或臨時出現的資訊為主     |
| 分析     | 趨勢、發生率、閾值、地區與族群比較 | 篩選、查證、風險評估及決定是否調查 |

# 3. 台灣指標式監測的四項案例

| 系統                  | 主要來源                                 | 分析／用途                                  | 閱讀提醒                     |
| --------------------- | ---------------------------------------- | ------------------------------------------- | ---------------------------- |
| 法定傳染病通報／NIDRS | 醫療與衛生單位通報，串接電子病歷、檢驗等 | 疑似個案、重要監測及群聚事件通報至研判      | 通報、研判與確定病例狀態不同 |
| RODS                  | 急診診斷碼、年齡與醫院等資料             | 依 ICD 對應類流感、腸病毒、腹瀉等症候群趨勢 | 診斷碼與症候群不等於病原確診 |
| 肺炎與流感死亡監測    | 死亡通報與死因欄位                       | 以關鍵字等方式統計相關死亡趨勢              | 需留意死因填報、分類與延遲   |
| LARS                  | 醫院實驗室檢驗及收件資料                 | 陽性檢體、檢測量與病原體波動                | 陽性率須同看分母與檢測策略   |

# 4. 事件式監測平台與查證

| 平台／來源            | 運作觀念                                     | 注意                                 |
| --------------------- | -------------------------------------------- | ------------------------------------ |
| HealthMap             | 整合網路疫情資訊，以文字處理、分類與地圖呈現 | 地圖上的訊號仍需看來源、日期與可信度 |
| GPHIN                 | 自動蒐集多語新聞，再由分析人員評估與提供情報 | 不是完全免人工的自動判定系統         |
| 新聞、社群、ProMED 等 | 補捉異常事件，與官方及其他來源交叉查證       | 相同消息大量轉載不代表多個獨立證據   |

本章記載 **GPHIN 於 1998 年由 WHO 與加拿大政府衛生部合作發展**；2004 年第二代整合七種語言，24 小時自動蒐集新聞、過濾與排序，提供衛生決策人員判斷及調查。

# 5. 2009 年 H1N1 案例：疫情階段與監測組合

| 階段         | 本章描述的監測重點                         | 要理解的機制                           |
| ------------ | ------------------------------------------ | -------------------------------------- |
| 國外出現警訊 | 2009 年 4 月掌握美國及墨西哥異常情況       | 事件式情報支援預警與整備               |
| 國內尚無病例 | 蒐集國外事件，準備病例、檢驗與就醫監測     | 早期警訊與既有系統同時運作             |
| 疫情進入國內 | 以指標式追蹤病例、類流感門急診、住院及死亡 | 比較國內趨勢與疾病負擔；事件式持續補充 |
| 大規模接種後 | 連結接種與診斷資料，追蹤特別關注不良事件   | 比較背景、未接種或非風險期發生情形     |

本例重點是==依疫情階段調整資訊需求，同時保留兩種監測的互補性==。

# 6. 五項發展方向與案例

## 6.1 整合相關監測資料

整合不同系統與電子病歷，減少人工重填、重複資料及資訊孤島。整合時需確認定義、代碼、病人連結、資料時間與品質；把資料放進同一庫，不代表語意已一致。

## 6.2 系統效能與行動科技

| 案例             | 本章重點                                | 適合記憶的觀念                                     |
| ---------------- | --------------------------------------- | -------------------------------------------------- |
| NIIS             | 2017 年改版採較集中化架構、介接外部服務 | 接種資料同步、擴充與共享                           |
| 健康存摺         | 讓民眾查閱個人接種等健康資料            | 個人資訊取用與健康管理                             |
| EU-DCC／SHC      | 2021–2022 年數位新冠健康證明格式案例    | 跨境資料格式與可驗證證明，不等於永遠有效的入境資格 |
| e-DOTS           | 視訊觀察結核病人服藥                    | 減少訪視交通限制，仍須合適流程與支持               |
| 疾管家           | NLP／互動式防疫資訊查詢                 | 官方資訊服務與風險溝通                             |
| Taiwan V-Watch   | 接種後健康回報及追蹤                    | 追蹤接種後的健康狀況                               |
| 臺灣社交距離 App | 以藍牙訊號估計接近與接觸時間            | 透過藍牙估計接近距離與接觸時間，協助暴露通知       |

## 6.3 大數據與非結構化資料

- **疫情儀表板**：整合趨勢、地區與重要指標，支援決策及溝通。
- **登革熱群聚地圖**：利用空間統計與資料整合呈現風險，同時保護個人隱私。
- **流感預報**：本章結合類流感、健保、氣象及人口資料，以機器學習預估未來四週趨勢。

## 6.4 開放資料加值

政府提供合適的開放資料，外部單位可開發接種管理、標準化發生率地圖及其他服務。本章列「萌寶日記」等歷史合作案例，重點是公私協作與資料再利用。

## 6.5 新興科技與分析

本章列線上分析、統計模型、GIS、電子郵件／簡訊預警、物聯網、穿戴裝置、區塊鏈、遠距醫療及精準醫學。實務判斷應從監測目的出發，評估科技能否改善資料取得、品質、時效、可及性與行動結果。
