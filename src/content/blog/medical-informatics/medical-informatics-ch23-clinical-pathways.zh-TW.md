> [!IMPORTANT]
> **重要考點**
>
> - **臨床路徑＝跨專業＋時間表＋預期成果＋差異管理**，用來改善品質並控制不必要成本。
> - **DRG／論病例計酬**與臨床路徑的標準化及成本管理相關；勿把題目中的「論病例」換成「論量」。
> - 套裝醫令三類：==個人、系統、部門==；特殊模式三種：==輔助、快速、特定==。
> - 六類差異的固定名稱含**住院前差異**；別把它隨意換成其他類名。
> - 優點方向是縮短不必要住院、降低費用、減少併發症及改善品質；「延長住院日」是反向錯項。

# 1. 住院醫令系統的定位與導入

早期曾採紙本與電子並用的雙軌作業；本章強調系統應配合醫護工作、降低學習及輸入負擔，讓輪科與新進人員容易掌握。導入需有工作站、網路、標準化資料、策略及足夠維護人力。

# 2. 醫令設計的七項必備條件

| 條件       | 意義                                   | 重點                                     |
| ---------- | -------------------------------------- | ---------------------------------------- |
| 醫令混合性 | 藥品、檢驗及處置可從一致的作業入口處理 | 配合醫師開單順序，減少在不同模組來回切換 |
| 醫師習慣   | 以熟悉、明確的方式提供資料             | 簡便不代表省略安全必要欄位               |
| 用藥差異   | 支援不同頻率、途徑及特殊排程           | 能清楚表示交替劑量、隔日或不規則用法     |
| 套裝醫令   | 減少常見情境的重複輸入                 | 按病人情況選取、刪除與修改               |
| 醫令儲存   | 儲存常用內容，供日後參考               | 範本需維護並防止錯誤持續複製             |
| 醫令建議   | 結合年齡、病況、診斷及治療計畫提供支援 | 建議不直接等同最適合每位病人的決定       |
| 醫令警示   | 提醒過敏、器官功能或其他風險           | 需有適當優先度、可理解原因與處理記錄     |

## 2.1 三類套裝醫令

| 類型     | 本章英文                        | 設定依據                 |
| -------- | ------------------------------- | ------------------------ |
| 個人套裝 | Physician order sets            | 個別醫師的常用設定       |
| 系統套裝 | System order sets               | 特定疾病、手術或特殊情況 |
| 部門套裝 | Official order sets（本章用語） | 科別或部門共同標準       |

例如同一疾病可能分入院、每日、術前、術後及出院醫令組。==醫令組是一組開立項目，臨床路徑還包含時間安排、成果與差異檢討==。

# 3. 五種輸入方式

1. **鍵盤**：直接輸入或配合快捷操作。
2. **指標裝置**：滑鼠、光筆、軌跡球等。
3. **條碼掃描**：輔助辨識或選取相關項目。
4. **語音辨識**：把語音轉為可處理輸入，仍須核對辨識結果。
5. **手寫辨識**：以平板等裝置輸入，仍須確認轉換正確。

# 4. 系統設計的十項功能

| 功能              | 本章案例／設計目的                                                 |
| ----------------- | ------------------------------------------------------------------ |
| 1. 遠端開立       | 不限單一護理站，可於授權環境處理；遠端仍需身分驗證、權限與安全連線 |
| 2. 多功能畫面     | 同一介面處理不同類別醫令及必要資訊                                 |
| 3. 特殊醫令模式   | 輔助、快速及特定情境模式，見下表                                   |
| 4. 特別組合顯示   | 篩選目前用藥、已開處方或尚未執行醫令                               |
| 5. 顯示相關醫令   | 開單時看見既有項目與結果，協助辨識不必要的重複                     |
| 6. 暫存醫令       | 工作中斷可保存草稿並稍後續作                                       |
| 7. 簡易輸入輸出   | 清單、自填欄位、範本與藥物／費用資訊                               |
| 8. 直接傳至各部門 | 藥局、影像、檢驗及護理端取得相關工作                               |
| 9. 改進照護品質   | 在開方時提供過敏、檢驗與病人特性等資訊                             |
| 10. 減少浪費      | 提示成本、已有醫令及適當替代選項，仍以必要照護為前提               |

| 特殊模式 | 核心                       | 本章例子                                             |
| -------- | -------------------------- | ---------------------------------------------------- |
| 輔助模式 | 開立時顯示與決策相關的資料 | 備血時顯示血色素與血型；用藥時提供血壓及既用藥等資訊 |
| 快速模式 | 直接輸入常用醫令           | 減少多層選單操作                                     |
| 特定模式 | 針對特定病況或流程設計     | 連續血糖資訊、轉科資料及會診資料整合                 |

==暫存草稿、已確認醫令與已執行醫令要清楚區分==。草稿未送出時不能讓執行單位誤認已正式生效；重新取出草稿也要檢查病人及資料是否改變。

# 5. 導入反應、用藥安全與出院摘要

## 5.1 系統既能減少錯誤，也可能引入新錯誤

本章討論以電腦醫令改善手寫辨識、傳達及資訊不足的問題，也指出電腦醫令仍可能產生錯誤，需要監測與改善。

## 5.2 出院摘要

住院時逐步累積診斷、重要病史、治療及檢查資料，系統可產生摘要草稿，醫師再依實際病程修正確認。資料自動帶入可減少重複輸入，不能確保自動內容必然完整或正確。

# 6. 臨床路徑的定義與相關概念

由醫師、護理、行政及其他相關專業共同設計，針對某疾病或手術，把評估、檢查、治療、用藥、活動、營養、衛教及出院安排放入時間軸，設定預期成果，執行後分析差異並改善。

| 概念            | 主要回答的問題                                       |
| --------------- | ---------------------------------------------------- |
| 臨床路徑        | 這類病人由哪些人，在何時完成哪些照護並達到什麼成果？ |
| 醫令組          | 某個情境可一起選取哪些醫令？                         |
| 個案管理        | 如何依個別需求協調跨單位、跨階段的照護與資源？       |
| DRG／論病例計酬 | 如何分類病例及決定支付？                             |

# 7. 施行前的準備與目標選擇

## 7.1 六項準備

1. **詳盡計畫**：列出從選題、設計、實施到差異檢討的完整流程。
2. **多元組織**：納入相關單位並建立共識，避免只由單一職類主導。
3. **定期教育**：讓臨床與行政理解目的、方法與分工。
4. **明確目標**：設定適合的疾病／手術及可評估成果。
5. **醫師參與**：結合專業、臨床領導及每日推動。
6. **護理參與**：利用第一線持續觀察、記錄、協調及回饋。

## 7.2 選題原則

優先考慮病人多、流程較能標準化的疾病或手術；本章另列住院日長、費用高及醫護有改善意願等條件。複雜且變異大的個案可能需個案管理，也可把路徑與個案管理並用。

# 8. 必要文件與路徑表

| 文件             | 內容與目的                                       |
| ---------------- | ------------------------------------------------ |
| 發展小組說明文件 | 施行流程圖、重要臨床步驟、角色與方法             |
| 臨床路徑表       | 以時間及照護項目呈現預期工作，記錄實際進度       |
| 差異報表         | 病人、日期、差異代碼、原因、處理、簽名及改善日期 |
| 差異號碼系統     | 以共同代碼分類，方便統計及電腦化                 |

**重要臨床步驟**：延誤後會明顯影響整體療程的關鍵節點，需在訓練與監測中特別注意。

# 9. 建立、施行與持續修正

## 9.1 建立的三步與五階段

1. **選擇目標**：可由 DRG／病種資料找出優先改善項目。
2. **找尋基準醫師及臨床領導**：由具專業與推動能力者參與。
3. **建立院內適用路徑**：發展小組 → 依實證設計 → 施行 → 結果分析 → 持續檢討。

## 9.2 施行的六項工作

| 工作           | 具體做法                                   |
| -------------- | ------------------------------------------ |
| 詳細記錄       | 從入院起每日記錄實際照護與結果，留下負責人 |
| 察覺與修正差異 | 及早討論偏離原因，必要時調整照護計畫       |
| 對照預期成果   | 出院後比較實際與預期，找出可改善因素       |
| 成果報告       | 回饋相關醫護與管理者，支持自我監測         |
| 推廣共識       | 讓相關單位理解效益與實作方式               |
| 個案管理       | 對複雜、高需求或不適合標準路徑者個別協調   |

系統可按路徑提示每日醫令、追蹤未完成工作、協助差異編碼與統計。

# 10. 差異管理：六類分類

| 本章分類                  | 例子                                           | 改善方向                               |
| ------------------------- | ---------------------------------------------- | -------------------------------------- |
| 1. 無差異                 | 按預定路徑完成                                 | 與「未納入路徑」分別標示，避免分母混淆 |
| 2. 住院前差異             | 急診入院、轉院、拒絕住院、前置檢查未完成       | 入院協調、前置作業與資訊銜接           |
| 3. 病人相關差異           | 併發症、反應不如預期、需改變治療或心理社會因素 | 依病況調整，必要時跨專業支持           |
| 4. 醫師／照護人員相關差異 | 開單延誤、執行延誤、支援服務延誤               | 分析責任與流程，避免只歸咎單一職類     |
| 5. 系統／醫院差異         | 排程壅塞、設備不足或故障                       | 容量、排程、備援及維護改善             |
| 6. 出院差異               | 家庭支持不足、照顧安排或未解決健康需求         | 及早出院準備、社福及照護資源連結       |

## 10.1 差異代碼例子

差異代碼以院內分類案例說明：

| 代碼群  | 主題                     | 例子                                          |
| ------- | ------------------------ | --------------------------------------------- |
| 100–105 | 符合、取消與入院前作業等 | 103 前置檢查未完成；104／105 因醫師／醫院改期 |
| 120–125 | 住院前／轉院等           | 121 急診入院；122 轉院；124 拒絕住院          |
| 130–134 | 病人相關                 | 131 併發症；132 改變治療；133 心理社會延誤    |
| 140–144 | 照護與服務延誤           | 141 開單；142 護理；143 支援服務              |
| 150–153 | 醫院與設備               | 151 排程超額；152 設備損壞                    |
| 160–164 | 出院                     | 161 家庭支持不足；163 未解決健康問題          |

# 11. 優點、失敗原因與成果解讀

## 11.1 五項預期優點

改善照護流程與協調、提高成果及品質、縮短可避免的住院日、減少不必要費用、降低部分併發症。本章「避免治療系統故障」較適合理解為減少流程失靈與照護缺口，不是保證設備永不故障。

## 11.2 九項失敗原因

1. 缺乏臨床醫師參與。
2. 醫師反彈且未處理原因。
3. 缺少跨專業、多單位組織。
4. 行政與醫護溝通不良。
5. 目標不明確。
6. 目標或路徑表不切實際。
7. 文件不實用、增加負擔。
8. 差異報表及檢討不適當。
9. 缺少護理人員參與。

## 11.3 十八種臨床路徑的成效案例

以下是**1996–1998 年林口長庚泌尿科前後比較**，不是現行全國平均：

| 指標           | 實施前    | 實施後    | 解讀                          |
| -------------- | --------- | --------- | ----------------------------- |
| 平均住院日     | 5.5 日    | 4.9 日    | 約減少 10.9%，p＜0.01         |
| 平均總住院費   | 53,448 元 | 46,562 元 | 約減少 12.9%，p＜0.01         |
| 檢驗費         | 2,561 元  | 2,495 元  | p＝0.62，未達本章常用顯著水準 |
| 術後併發症     | 1.4%      | 0.5%      | p＝0.02                       |
| 術後死亡       | 0.2%      | 0.1%      | p＝0.53，不能宣稱已證實降低   |
| 兩週同病再住院 | 1.3%      | 0.8%      | p＝0.18，不能宣稱已證實降低   |

# 12. 支付制度、推廣目標與發展方向

**論病例計酬與臨床路徑**：本章以 1997 年台灣支付制度背景說明，把適當照護項目納入路徑，可協助回應給付及品質要求。支付制度與規則會變動，本章病例與比例只代表當時案例。

本章提出的四項推廣目標：

1. **常規化**：融入每日記錄、執行及差異討論。
2. **擴大適用範圍**：有評估地發展更多合適路徑。
3. **電腦化**：與住院醫令結合，提供階段醫令及差異提醒。
4. **網路與決策支援整合**：協助建立路徑、統計差異及評估成果。
