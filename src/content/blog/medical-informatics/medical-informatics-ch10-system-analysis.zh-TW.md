> [!IMPORTANT]
> **重要考點**
>
> - 本章反覆考的是==委外的三項優勢：規模、經驗、專業化==。
> - **費用低廉不是保證；不能用有限經費要求超出成本的建置**。這是最重要的反向選項。
> - 其餘依序掌握：推動委員會決策、專案負責人統籌、系統總負責人整合、子系統負責人執行。
> - 需求訪談要留下**訪談紀錄與事務流程圖**，並讓使用者理解後確認。

# 1. 資訊系統的開發方式

## 1.1 自行開發與委外比較

| 面向       | 自行開發                                 | 委外開發                               |
| ---------- | ---------------------------------------- | -------------------------------------- |
| 主要執行者 | 醫院資訊部門                             | 外部專業廠商，與院方共同推動           |
| 重要條件   | 人力、技術、教育訓練、持續維護能力       | 適當廠商、明確合約、院方配合與管理能力 |
| 可能優勢   | 對院內作業熟悉，可持續累積知識與調整功能 | 可使用廠商跨院經驗、專業分工及規模效益 |
| 主要挑戰   | 開發負擔、人員流動、能力培養與知識延續   | 需求落差、責任不清、合作及交接問題     |
| 醫院的角色 | 開發者與使用者                           | 需求提出者、決策者、確認者與驗收者     |

## 1.2 委外的三大優勢

1. **規模**：設備採購與使用較有效率，可能有較好的議價能力；人員與管理資源較多樣。
2. **經驗**：廠商可累積不同客戶與專案的建置經驗，辨認常見問題。
3. **專業化**：可配置不同領域人才，持續研究技術與改善方法。

> [!IMPORTANT]
> **委外不等於移交全部責任**
>
> 醫院必須提供作業知識、派員參與、確認需求與成果，並編列合理資源。三項優勢是選擇委外的理由，並非每一家廠商都必然具備。

# 2. 合約的十五項重點

| 項次 | 項目         | 要確認的內容                                                     |
| ---- | ------------ | ---------------------------------------------------------------- |
| 1    | 工作範圍     | 應用軟體、硬體、網路及功能邊界；套裝系統的功能、畫面、型錄等附件 |
| 2    | 建置時程     | 起訖時間、檢查點、各階段交付物，及延誤責任、展延處理             |
| 3    | 價格與付款   | 總價、階段付款金額及付款條件                                     |
| 4    | 執行組織     | 雙方的職責、分工與配合事項                                       |
| 5    | 分析設計審查 | 文件審閱、書面意見、回覆期限及修改再送審方式                     |
| 6    | 專案文件     | 文件種類、格式、份數與交付要求                                   |
| 7    | 驗收         | 軟體、硬體及網路的驗收標準與程序                                 |
| 8    | 教育訓練     | 課程內容、對象與時數                                             |
| 9    | 保固維護     | 範圍、期間、耗材、故障處理及恢復時限                             |
| 10   | 保密         | 機密與專有資訊的保護、處理責任及違約約定                         |
| 11   | 智慧財產權   | 設備、文件與工作成果等權利歸屬                                   |
| 12   | 履約保證     | 保證的提供及返還程序                                             |
| 13   | 終止         | 終止事由與雙方後續責任                                           |
| 14   | 合約變更     | 書面約定變更、版本及雙方確認方式                                 |
| 15   | 爭議處理     | 雙方約定的處理程序或仲裁等機制                                   |

記憶方式：**做什麼、何時做、多少錢、誰來做、如何審、交什麼、怎麼驗、怎麼教、怎麼修、如何保密、成果歸誰、如何保證、如何終止、如何變更、如何解決爭議。**

# 3. 專案團隊的組成與分工

## 3.1 十種角色對照

| 角色             | 主要責任                                                             | 辨識關鍵                                     |
| ---------------- | -------------------------------------------------------------------- | -------------------------------------------- |
| 推動委員會       | 審議發展方向、目標及範圍；確立部門權責、協調意見、評估成果並推動執行 | **方向與授權**；由院長／副院長及相關主管參與 |
| 專案負責人       | 統籌時程、品質、成本，規劃監督，處理內外部溝通及衝突                 | **整個專案的管理窗口**                       |
| 醫務流程規劃顧問 | 評估流程合理性及可行性，協調跨系統醫療作業                           | **作業流程**                                 |
| 品質控制小組     | 監督品質流程，審核問題處理程序，提供意見及成果評估                   | **品質監督**                                 |
| 系統總負責人     | 制定發展程序、品質規範及時程，協調系統間工作                         | **跨系統整合**                               |
| 各子系統負責人   | 訪談、分析、設計、撰寫程式、測試、上線、維護；製作文件及手冊         | **各系統的實際建置**                         |
| 資料庫管理負責人 | 資料規劃、轉檔、建檔、上帶、清檔、備份、核對及效率評估               | **資料的正確與可用**                         |
| 硬體工程負責人   | 軟硬體架設配合、維護，以及網路工程監督與執行                         | **設備與基礎設施**                           |
| 教育訓練負責人   | 安排課程、時程、本章、講師與學員                                     | **使用者訓練**                               |
| 行政支援負責人   | 行政協調、資料處理、影印與文件整理                                   | **行政作業支援**                             |

## 3.2 溝通、授權與人員異動

- **單一窗口**：本章建議院方與廠商各有專案負責人，正式決議透過明確管道發布。
- **高階授權**：正式任命、明確職責，才能協調跨部門資源。
- **投入程度**：本章強調專案負責人應專注專案；其他角色是否兼任，依規模與工作量安排。
- **正式交接**：人員異動需事先通知、交接現況與困難、檢討後續進度，並提供訪談紀錄、流程及說明文件。

> [!WARNING]
> **常考差別**
>
> **推動委員會**決定方向及授權；**專案負責人**控制整體專案；**系統總負責人**統合系統建置；**子系統負責人**完成所屬系統的具體工作。

# 4. 需求訪談

## 4.1 訪談前、中、後

| 階段   | 工作重點                                                             | 應留下的成果                           |
| ------ | -------------------------------------------------------------------- | -------------------------------------- |
| 訪談前 | 研究醫療流程與背景資料；釐清主題；約定次數、時間及參與人員           | 訪談計畫、時程表、問題清單             |
| 訪談中 | 用使用者能理解的語言與圖形；掌握主題及時間；詢問例外情形與跨單位關係 | 具體事實、流程、規則、問題及待確認事項 |
| 訪談後 | 整理紀錄、請使用者確認、修正差異，建立業務流程文件                   | 確認後的訪談紀錄、事務流程圖           |

本章要求訪談紀錄於訪談後 **三天內**送使用者確認。考題依本章作答時可記住「三天」；實際執行仍應在專案計畫中明定期限。

## 4.2 溝通的兩個陷阱

1. **空手訪談**：完全不做領域準備，期望使用者替分析師建立完整系統架構，容易降低信任且遺漏問題。
2. **只交技術文件**：使用者看不懂 DFD 或技術術語，即使簽認也可能沒有真正理解。
