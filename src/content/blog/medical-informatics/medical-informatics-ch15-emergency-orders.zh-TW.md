> [!IMPORTANT]
> **重要考點**
>
> - 先抓急診與門診的核心差異：==檢傷分類與依急迫性決定處置優先序==。
> - **五級順序：復甦急救、危急、緊急、次緊急、非緊急**；第一級是復甦急救。
> - 臨床優先序與費用規則要分開：檢傷決定優先序；基本部分負擔表按**院所層級**列金額。
> - **暫存、完診、留觀、出院、已簽收、已有報告**是不同狀態。

# 1. 急診環境對資訊系統的要求

| 環境特性               | 系統需求                                           |
| ---------------------- | -------------------------------------------------- |
| 身分可能不明、證件未帶 | 暫時身分與必要欄位先建檔，後續核對補齊             |
| 病況急迫、可能惡化     | 檢傷優先序、持續評估、危急值與預警通知             |
| 同時跨多單位           | 醫令傳送、簽收、檢驗／影像回報、會診與住院銜接     |
| 醫護操作頻繁           | 常用功能容易取得、快速搜尋、合理預設、減少重複輸入 |
| 病人移動與停留多       | 病人動向、位置、候診及留觀追蹤                     |

# 2. 一般作業流程

急診病歷的主訴、病史、診斷、檢查結果及已執行治療，應支援住院端判斷與疾病分類。

# 3. 急診檢傷分類

## 3.1 五級分類

| 級別 | 中文     | 英文                   | 記憶             |
| ---: | -------- | ---------------------- | ---------------- |
|    1 | 復甦急救 | Resuscitation          | 需立即急救       |
|    2 | 危急     | Emergent               | 高急迫性         |
|    3 | 緊急     | Urgent                 | 仍需及時評估處理 |
|    4 | 次緊急   | Less urgent            | 相對較低急迫性   |
|    5 | 非緊急   | Non-urgent／Not urgent | 五級中急迫性最低 |

檢傷綜合病情、主訴及客觀資料，六種調節變數為：**呼吸窘迫度、血行動力、意識程度、體溫、疼痛程度、受傷機轉**。

# 4. 急診掛號與病人識別

五項重點：

1. 記錄基本資料、看診時間與醫師等資訊。
2. 支援匿名／暫時身分及退掛、改掛、欠費等情境。
3. 保存檢傷等級，必要資料可在病況穩定後補齊。
4. 連結急診病歷、醫令及批價作業。
5. 記錄就診科別與轉科資訊，依院內組織設定。

# 5. 狀態管理：三張表分清楚

## 5.1 看診狀態

| 狀態 | 本章定義                                   |
| ---- | ------------------------------------------ |
| 候診 | 已掛號，尚未開始診察                       |
| 暫存 | 診察尚未結束，可能等待檢驗、影像或治療結果 |
| 完診 | 本階段診察處置已完成，後續可能出院或住院   |
| 留觀 | 決定需繼續觀察與後續處置                   |

==完診不等於已出院；暫存不等於醫令已執行。== 系統宜讓常用候診清單預設顯示，並可切換其他狀態。

## 5.2 病人動向／後續處置

本章範例包含：**自動出院、待床、到院後死亡、到院前死亡、不告而別、准許出院、未會診、留觀、退掛、拒絕留觀**。其中「自動出院」為原系統的狀態名稱，不能解讀成程式自動替病人作出臨床出院決定。

## 5.3 醫令執行狀態

| 狀態     | 意義                                             |
| -------- | ------------------------------------------------ |
| 已開立   | 醫師已提出指令，不代表已執行                     |
| 未簽收   | 執行單位尚未受理，依權限可調整                   |
| 已簽收   | 執行單位已受理；本章範例禁止直接修改或刪除       |
| 已有結果 | 結果產生並回報，不表示醫師已閱讀或已完成後續處置 |

# 6. 急診醫令系統的功能

## 6.1 輸入的六大類

**用藥、其他處置醫令、檢驗、影像檢查、衛材、醫令套餐**。影像類包含 X 光、CT、MRI 等。

## 6.2 用藥欄位與快速輸入

| 欄位／功能                         | 設計重點                                                 |
| ---------------------------------- | -------------------------------------------------------- |
| 藥名、劑量、頻率、單位、途徑、天數 | 構成完整處方，不可只確認藥名                             |
| 自動帶入                           | 由藥品基本資料帶入預設內容，仍須確認病人適用性           |
| 跳欄與快速搜尋                     | 減少重複鍵入，讓醫師容易修改                             |
| 醫囑單位                           | 開立劑量使用的單位                                       |
| 計價單位                           | 藥品計費的單位，可能須與劑量單位換算                     |
| 總量                               | 依頻率、天數、劑量及單位換算；特定頻率仍須依實際規則計算 |
| 磨粉、自費別                       | 反映調劑與費用需求，不能取代藥品適宜性審查               |

## 6.3 常用項目、套餐、同上

| 功能                                 | 來源／內容                                 | 優點與核對重點                                   |
| ------------------------------------ | ------------------------------------------ | ------------------------------------------------ |
| 常用藥／常用處置／常用衛材／常用診斷 | 維護檔預先建立的常用選項                   | 快速找項目；需持續更新內容                       |
| 醫令套餐 Order set                   | 將診斷、藥品、處置、檢驗及影像等組合       | 一次帶入多項；仍須依病況增刪並避免重複           |
| 同上 Ditto                           | 複製歷次門診、急診或住院資料與醫令         | 減少輸入；需確認當次主訴、診斷、過敏、用藥與需求 |
| 檢驗／影像開單                       | 帶入本次就診資料，依類別及檢體選取         | 檢驗可依檢體、代碼、名稱查詢；核對部位與項目     |
| 會診                                 | 帶入病人資料，選科別及醫師，記錄通知與結果 | 保存申請、聯絡、到達、結束時間；取消時記錄原因   |

## 6.4 完成、暫存與取消

- **完成**：本階段就診完成，送出或列印必要醫令、檢驗單及藥局資料。
- **暫存**：尚需等待結果或後續處理，保留工作內容。

# 7. 批價與費用規則

## 7.1 概念要分開

| 項目                   | 意義                                                           |
| ---------------------- | -------------------------------------------------------------- |
| 掛號費                 | 院所行政收費項目                                               |
| 診察費／醫令費／藥品費 | 醫療服務費用與申報項目                                         |
| 部分負擔               | 保險對象依規定自行負擔的部分                                   |
| 自費                   | 不由健保給付或按規定由病人自付的項目                           |
| 支付點數               | 健保支付計算的點數；不能直接把表列點數視為病人需付的新臺幣金額 |

本章的急診批價分為：**從醫令系統帶入的批價**，以及**未經醫令系統流程時的補輸批價**。範例限制批價人員只能補鍵衛材；藥品或處置有疑義應請醫師處理，避免行政人員擅改臨床指令。

## 7.2 加成邏輯

由醫令基本資料帶出適用加成，再判斷急診、年齡等條件。本章將兒童區分未滿六個月、六個月至兩歲、兩歲至六歲，說明不同年齡可能有不同加成；但各醫令能否併算及加成方式，仍須依該項支付規則。

診察費範例列舉 2023 年診察費：01015C 急診診察費 667 點、01021C 精神科急診診察費 901 點，並描述夜間、例假日及資源不足地區加成。這些是**本章所列的歷史版本**，不直接作為目前申報點數或通用加成公式。

## 7.3 急診基本部分負擔

| 院所層級 | 急診基本部分負擔 |
| -------- | ---------------: |
| 醫學中心 |           750 元 |

基本部分負擔表標示 **2023-07-01 起適用**；不區分檢傷分類，按就醫院所層級定額收取。

# 8. 緊急醫療管理與跨院整合

災害或大量傷病患事件需要共享空床、可用人力、設備及病人資訊，以協調資源、轉院及救護。單院急診醫令系統之外，還需要跨院的緊急醫療管理網路。

# 9. RFID 與 NFC 的急診應用

| 應用           | 可支援的工作                               |
| -------------- | ------------------------------------------ |
| 身分辨識       | 讀取腕帶後連結病人資料，輔助核對           |
| 動向與流程追蹤 | 記錄病人經過的流程及停留時間，分析等待原因 |
| 床邊資訊       | 整合病歷、檢查結果與用藥提醒               |
| 照護互動紀錄   | 記錄人員接觸與照護流程，支援追蹤           |
| NFC            | 以近距離感應作識別入口，結合其他系統應用   |

# 10. 未來整合方向

1. **急重症照護**：串接救護車與院前生命徵象、遠端協作，銜接到院後照護。
2. **轉診、轉檢及代檢**：分享必要檢查結果、床位及資源，減少重複作業。
3. **感染監測**：由急診資料偵測異常趨勢，結合感染控制與決策支援。
4. **疾病與緊急狀態預測**：利用生理訊號、影像及 AI 輔助風險辨識與優先順序調整。
