> [!IMPORTANT]
> **重要考點**
>
> - **CDSS＝Clinical Decision Support System；Ditto＝複製前次內容**。
> - 架構演進先記：==大型主機／終端機 → 主從架構 → 三層架構==。
> - **To Err Is Human → 醫療錯誤與病人安全**，不是網路駭客或交通安全報告。
> - 四大子系統：診療記錄建立、醫療排程、病歷查詢列印、門診綜合作業。
> - 資訊閉環要追到執行、回報、確認及後續處置；傳送成功只是一個節點。

# 1. 定位與五項目的

| 目的                  | 具體意義                                   |
| --------------------- | ------------------------------------------ |
| 1. 正確且完整的資料   | 病人身分、診斷、處方與處置保持一致         |
| 2. 即時取得歷次記錄   | 紙本尚未送達時，仍可查閱已有的電子資料     |
| 3. 整合報告與排程     | 取得檢驗影像結果，安排後續檢查或治療       |
| 4. 提醒申報與給付規則 | 提示適應症、數量、天數等限制，降低行政疏漏 |
| 5. 支援安全及決策     | 納入過敏、交互作用、重要檢驗與高危險訊息   |

# 2. 建置的十項考量

| 項目                | 核心問題               | 本章重點                               |
| ------------------- | ---------------------- | -------------------------------------- |
| 1. 整體效益         | 是否改善照護及作業？   | 評估品質、效率、成本與使用負擔         |
| 2. 作業平台相容性   | 能否連接既有系統？     | 介面、資料及設備須整合                 |
| 3. 系統穩定性       | 忙碌時是否可靠？       | 正確傳送、故障復原、問題迅速處理       |
| 4. 工作流程配合     | 是否造成過多額外工作？ | 納入醫護實際作業，改善導入期負擔       |
| 5. 個人化與組合設定 | 是否容易輸入常見內容？ | 常用藥、診斷、處置、醫令組及個人設定   |
| 6. 資訊閉環         | 後續處理有沒有完成？   | 從開立到簽收、執行、回報及處置都能追蹤 |
| 7. 智慧化           | 如何協助決策？         | 以適當規則或模型結合病人資料提供支援   |
| 8. 技術可行性       | 是否能實作並擴充？     | 評估整合難度、維護、資安及後續發展     |
| 9. 開發與維護模式   | 自建或委外如何取捨？   | 人力、主導權、溝通、修復及升級能力     |
| 10. 使用介面與教育  | 使用者能否正確操作？   | 簡潔介面、快捷鍵、選單、觸控與角色訓練 |

## 2.1 平台演進與三層架構

1. **展示層**：顯示資料、接收使用者輸入。
2. **商業邏輯層**：處理醫令規則、流程及檢核。
3. **資料存取層**：存取資料庫及相關資料服務。

## 2.2 資訊閉環：考試最重要的流程觀念

==只把資料送到另一台電腦，不算完整閉環==。異常、拒收、取消與逾時同樣要能追蹤。

## 2.3 便利輸入與權限

常用語、巨集、醫令組與複製前次內容可減少操作時間，但須重新確認當次病情、過敏、劑量及已停用項目。個人化不能使過時設定持續套用。

# 3. 四大功能子系統

## 3.1 診療記錄建立

| 輸入類別       | 內容                                           | 容易混淆處                             |
| -------------- | ---------------------------------------------- | -------------------------------------- |
| 主觀資料 S     | 主訴、症狀及病人陳述                           | 不與測得數據混為一談                   |
| 客觀資料 O     | 理學檢查、生命徵象及檢查結果                   | 應保留時間及必要單位                   |
| 評估 A         | 診斷與臨床評估，連結診斷碼                     | 有代碼不等於已完整表達評估             |
| 藥品處方 P     | 藥名、劑量、單位、頻率、途徑、天數、總量及註記 | 每次劑量與總量不同；給付註記與用法不同 |
| 處置及檢查     | 檢驗、影像、核醫等醫令                         | 項目、部位、必要條件及排程要正確       |
| 其他計畫與指示 | 檢查日期地點、營養及衛教等                     | 須讓病人理解並能採取行動               |

SOAP 的 **P 是整體計畫**，不只藥品處方；可包括檢查、處置、衛教與追蹤。複製舊 SOAP 或套用組合後，仍需當次審閱。

## 3.2 醫療排程

連結檢驗、影像、內視鏡及復健等服務，安排可用時段，提供日期與地點。完整安排還須讓執行單位、病人及開單端知道預約狀態，並處理改期或取消。

## 3.3 病歷查詢與列印

**六類查詢**：

1. 歷次 SOAP：依科別、日期等查詢，必要時參考前次記錄。
2. 重要病史：診斷、用藥、家族史、重要註記及過敏。
3. 病人與護理資料：人口學及生命徵象等。
4. 檢驗檢查報告：整合報告與相關結果。
5. 費用：查詢當次或相關醫療費用。
6. 藥品、給付規則與公告：支援開立與作業查核。

**三類列印去向**：

| 去向           | 本章案例                             |
| -------------- | ------------------------------------ |
| 診間           | 診療相關文件、申請單、檢查與衛教指示 |
| 服務櫃台       | 釋出處方箋等病人領取文件             |
| 藥局及執行單位 | 藥品、注射或化療相關標籤及單據       |

## 3.4 門診綜合作業

- **基本資料維護**：共同代碼、常用診斷、藥品、處置及檢驗資料。
- **個人與科別常用組合**：完整或部分 SOAP、常用醫令與表單。
- **文件作業**：入院許可、診斷書、轉診、自費同意及傳染病通報等。
- **回診預約**：銜接後續門診。
- **登入與角色管理**：辨識使用者並依權限提供功能。

# 4. 病人安全支援

**To Err Is Human** 的核心是醫療錯誤造成傷害，應提升病人安全；**Crossing the Quality Chasm** 也強調照護品質與安全。先辨認主旨，再讀個別系統功能。

## 4.1 資料整合與規則

將==病人、檢驗、診斷、藥品、處置==等資料連結後，才能支援病人情境相關的提醒。

## 4.2 四項病安案例

| 案例             | 縮寫／內容                       | 管理重點                              |
| ---------------- | -------------------------------- | ------------------------------------- |
| 藥物交互作用提醒 | DDIR，顯示相關藥品及交互作用依據 | 評估嚴重度與病人情境，留下處理理由    |
| 手術病人安全系統 | SPSS，核對病人、手術與部位／側別 | 串接排程與核對；此處不是統計軟體 SPSS |
| 高危險提醒       | HRR，重要或危急結果通知相關醫師  | 除發送外，需確認收訊、處置與追蹤      |
| 射頻辨識         | RFID 支援病人或物品辨識          | 標籤要正確綁定，讀取後仍需適當核對    |

# 5. 常考比較與記憶

| 比較               | 記法                                                     |
| ------------------ | -------------------------------------------------------- |
| CPOE 與 CDSS       | 前者輸入及流轉醫令；後者依資料與知識支援判斷，可整合使用 |
| 查詢與排程         | 查詢取得已有資訊；排程安排後續服務                       |
| 個人化與標準化     | 常用設定提高效率；共同規範確保安全與跨單位一致           |
| 傳送成功與閉環     | 傳送只是一個狀態；閉環追到執行、回報及處置               |
| SOAP 與處方        | SOAP 是記錄結構；藥品處方是計畫的一部分                  |
| 警示發送與處理完成 | 系統送出提醒後，還要有人收訊、判斷、採取行動並記錄       |

**十項建置考量口訣**：效益、平台、穩定、流程、個人化；閉環、智慧、技術、維護、介面。
