# 1. 為什麼需要醫療資訊標準？

| 問題                             | 具體情況                                           | 後果                         |
| -------------------------------- | -------------------------------------------------- | ---------------------------- |
| **編碼缺乏一致性**               | 同一項目有數個代碼；同一代碼代表不同項目           | 資料解讀與整合困難           |
| **臨床表達能力不足**             | 以計價、申報為主要目的的代碼，無法完整描述臨床內容 | 電子病歷不夠精確             |
| **交換格式不一致**               | 不同醫院，甚至同院不同系統採不同格式               | 維護、升級與交換困難         |
| **封閉系統與既有系統整合成本高** | 新系統須逐一銜接既有系統（legacy system）          | 程式再用性下降、開發成本增加 |

# 2. 標準形成的四種方式

| 類型               | 形成方式                                     | 本章例子                   | 辨識關鍵               |
| ------------------ | -------------------------------------------- | -------------------------- | ---------------------- |
| **任務導向標準**   | 有共同目標的人員或組織，基於互利需求共同訂定 | ACR 與 NEMA 合作發展 DICOM | 共同任務與專業需求     |
| **實質標準**       | 因廣泛使用或高市場占有率而自然形成           | Windows                    | 市場採用程度           |
| **政府強制型標準** | 透過政府規範要求遵循                         | 健保申報所需規範           | 法規或行政要求         |
| **共識型標準**     | 相關領域人員透過開放討論與程序形成共識       | HL7                        | 開放協商；形成時間較長 |

# 4. 醫療資訊標準的兩大面向

| 面向               | 解決的問題                       | 本章例子                                       |
| ------------------ | -------------------------------- | ---------------------------------------------- |
| **醫學詞彙及編碼** | 這個資料項目或概念代表什麼？     | ICD、SNOMED CT、LOINC、MeSH；另介紹 DRGs、UMLS |
| **資料交換**       | 系統間如何組織、傳送與解讀訊息？ | HL7、DICOM                                     |

# 5. 選擇醫學詞彙及編碼標準的四項考量

| 考量                 | 應問的問題                                 | 重點                                                              |
| -------------------- | ------------------------------------------ | ----------------------------------------------------------------- |
| **使用目的**         | 做摘要分類，還是完整記錄？                 | 區分資料摘要（data abstraction）與資料表達（data representation） |
| **應用領域**         | 用於支付、統計、臨床記錄，還是文獻檢索？   | 所需精細度（granularity）不同                                     |
| **編碼結構及組合法** | 串列、樹狀或網路狀？能否組合概念？         | 評估表達能力與擴充性                                              |
| **維護與更新**       | 誰維護？如何處理舊資料？需要授權或費用嗎？ | 包含向後相容性（backward compatibility）                          |

## 先組型與後組型

| 類型                            | 組合時間             |
| ------------------------------- | -------------------- |
| **先組型（pre-coordination）**  | 標準編製時就已組合好 |
| **後組型（post-coordination）** | 使用時依規則組合概念 |

# 6. 常用醫學詞彙與編碼系統

## 6.1 ICD-10-CM／PCS：疾病與處置分類

- **ICD** 原先的重要目的，是讓罹病與死亡統計可以跨地區、跨國比較。
- **CM** 指臨床修訂；**PCS** 指處置編碼系統。記憶時分清楚 ==CM 看診斷；PCS 看處置==。
- 本章回顧 ICD-9-CM 在臺灣健保給付中的使用，並指出舊式分類碼對解剖位置、嚴重度與臨床表現的表達及擴充能力有限。
- 只使用申報碼作為病歷的唯一描述，可能不足以保存完整的臨床細節；支付目的也可能影響編碼行為。
- 臺灣自 **2016 年 1 月 1 日**導入 ICD-10-CM／PCS 申報。

## 6.2 DRGs：診斷關聯群

- 依住院病例的診斷、治療與資源使用特性分組，作為支付制度的基礎。
- 本章列出的細分因素：**年齡、性別、合併症（comorbidity）、併發症（complication）、出院狀況**等。
- **Tw-DRGs** 是配合臺灣醫療制度發展的分組與支付制度；本章列 **2010 年 1 月 1 日**開始實施。
- ICD 記錄疾病與處置分類，DRGs 再利用相關資訊做病例分組；==DRGs 與 ICD 的功能不同==。

## 6.3 SNOMED CT：臨床概念的精細表達

- 著重**完整、彈性、一致的臨床概念表達**，適合電子病歷內容。
- 本章回顧的詞彙發展脈絡為 **SNDO → SNOP → SNOMED → SNOMED CT**。
- 支援後組型表達，能依規則組合概念描述複雜的臨床情況。
- 可與 ICD 等系統建立對映，以支援不同用途。

## 6.4 LOINC：檢驗與臨床觀察的識別

- 由 **Regenstrief Institute** 發展，用統一的名稱與代碼識別實驗室及臨床觀察項目。
- 回答的核心問題是 ==「測量／觀察的是什麼項目？」==。
- **RELMA** 協助把當地實驗室詞彙對映到 LOINC。
- 可配合 HL7 等交換格式，支援臨床照護、結果管理、公衛與研究。

## 6.5 MeSH：醫學文獻的主題詞

- 由 **NLM** 維護，採階層式的受控詞彙。
- 主要用於**文獻索引、編目與檢索**，包含 MEDLINE／PubMed 等醫學資訊來源。
- ==看到「醫學文獻、主題詞、檢索」就聯想到 MeSH==，和臨床病歷細節的記錄目的不同。

## 6.6 UMLS：整合不同醫學詞彙

- NLM 於 **1986 年**開始的醫學語言整合計畫，目標是串連不同詞彙中的概念與名稱。
- 本章列舉 ICD-10-CM、LOINC、MeSH、SNOMED CT 等來源詞彙。

| 三大知識來源                                 | 主要功能                                       | 記憶方式         |
| -------------------------------------------- | ---------------------------------------------- | ---------------- |
| **Metathesaurus（詞彙總集）**                | 依概念連結不同來源詞彙的名稱，保留相關概念關係 | 概念與名稱的整合 |
| **Semantic Network（語意網路）**             | 提供廣義語意類型及其關係                       | 概念類型及關係   |
| **SPECIALIST Lexicon（專家辭典）與詞彙工具** | 提供詞形、語法等語言資訊，協助 NLP             | 語言處理         |

## 六種系統快速比較

| 系統           | 最適合聯想的任務           | 關鍵提示                 |
| -------------- | -------------------------- | ------------------------ |
| ICD-10-CM／PCS | 診斷與處置分類、統計及申報 | 分類碼                   |
| DRGs           | 住院病例分組及支付         | 病例組合、資源使用       |
| SNOMED CT      | 詳細臨床概念表達           | 臨床語意                 |

| MeSH           | 醫學文獻索引與檢索         | 主題詞                   |
| UMLS           | 整合及連結多套詞彙         | 詞彙總集＋語意網路＋辭典 |

# 8. HL7 及相關標準

## 8.1 相關技術與用途

| 名稱             | 本章應掌握的功能                                      |
| ---------------- | ----------------------------------------------------- |
| **HL7 v2**       | 醫療系統間的訊息交換；本章回顧早期版本演進            |
| **HL7 v3**       | 以資訊模型為基礎的標準發展；本章強調物件導向及 XML    |
| **CDA**          | 定義交換用臨床文件的結構及語意                        |
| **Arden Syntax** | 醫療決策支援知識／規則的表達                          |
| **CCOW**         | 臨床應用程式的情境協調                                |
| **DCM**          | 詳細臨床模型，著重臨床資料的詳細表達                  |
| **FHIR**         | 以資源為基本單位的醫療資訊交換標準，結合常用 Web 技術 |

## 8.2 其他交換標準

- **MEDIX（IEEE P1157）**：本章介紹為依 OSI 架構設計的醫療資料交換標準，推廣程度不如 HL7。
- **IEEE 1073**：醫療監測儀器資料傳輸標準。

# 9. DICOM 與 PACS

## 9.1 起源與用途

- 由 **ACR＋NEMA** 合作推動，解決不同廠牌設備間影像與相關資訊的交換問題。
- **1983 年**成立聯合委員會；前身為 ACR-NEMA 標準。
- 除了影像檔案，也規範相關資料、通訊及服務行為。
- 常見場景：CT、MRI、數位 X 光、超音波、內視鏡等影像設備與影像系統的銜接。

## 9.2 DICOM 各部分

DICOM 各部分可按主題記憶。

| Part | 主題                         | Part | 主題                         |
| ---- | ---------------------------- | ---- | ---------------------------- |
| 1    | 介紹與全覽                   | 2    | 符合性                       |
| 3    | 資訊物件定義                 | 4    | 服務類別規格                 |
| 5    | 資料結構與編碼               | 6    | 資料字典                     |
| 7    | 訊息交換                     | 8    | 訊息交換的網路通訊支援       |
| 9    | 本章註記停用                 | 10   | 媒體儲存與檔案格式           |
| 11   | 媒體儲存應用規範             | 12   | 媒體交換的格式與儲存相關規範 |
| 13   | 本章註記停用                 | 14   | 標準灰階顯示功能             |
| 15   | 安全與系統管理規範           | 16   | 內容對映資源                 |
| 17   | 說明資訊                     | 18   | Web 服務                     |
| 19   | 應用程式託管                 | 20   | 使用 HL7 CDA 的影像報告      |
| 21   | DICOM 與其他表示法之間的轉換 | 22   | 即時通訊                     |

- 優先聯想：==3 物件、4 服務、5 結構、6 字典、7 訊息、8 網路、10 檔案、14 灰階、15 安全、18 Web==。

## 9.3 PACS 與 DICOM 的關係

- **DICOM 是標準**：協助影像設備與系統交換資料。
- **PACS 是系統**：提供影像儲存、管理、傳輸及取用等功能。
- ==買 PACS 是採購系統；要求支援 DICOM 是規範相容的交換能力。==

# 10. 為什麼還需要 IHE？

- 不同設備即使都宣稱支援 HL7 或 DICOM，仍可能因選項、實作及流程不同而無法互通。
- 本章介紹 **HIMSS 與 RSNA** 推動 IHE，透過技術架構說明不同系統的角色與互動。
- 核心概念：==把既有標準落實到具體臨床工作流程==。

| 名稱  | 解決的主要問題                               |
| ----- | -------------------------------------------- |
| HL7   | 醫療資訊如何交換                             |
| DICOM | 醫療影像與相關資訊如何交換                   |
| IHE   | 不同角色在特定工作流程中如何協同使用既有標準 |

# 11. 臺灣醫療資訊標準推動問題

推動問題包括：

- **委外建置**：採購與維護費用高，更新升級不易。
- **導入能力不足**：缺乏完善訓練、參考規範與顧問諮詢，可能導致建置受挫。
- **自行開發**：需要承擔資訊人員與持續維護的成本。
