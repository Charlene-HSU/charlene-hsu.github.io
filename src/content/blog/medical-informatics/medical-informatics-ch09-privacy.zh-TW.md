> [!IMPORTANT]
> **重要考點**
>
> - **多資料庫合作、不直接連結原始資料仍能算出結果 → 多方私密計算 MPC**。
> - **CellSecu 順序：Filter 過濾 → Confidentiality test 保密測試 → Generalize 概化**。
> - **知情同意＝充分告知後同意**；個人有查閱、複製、更正、停止利用及刪除等權利，「請求公開」不是同一份權利清單。
> - 資料中心題型：==申請審核、限定對象、受控場所使用==；不是去識別後就能買光碟或下載到個人電腦自由使用。
> - **健保資料二次利用：獨立監督、組織程序、停止利用／退出機制；判決補正期限三年**。

# 1. 隱私權與醫療資料的價值

- 隱私關乎個人對自身資訊的掌握，以及資訊如何影響人際、工作與社會關係。

# 2. 法律與同意機制

## 2.1 涵括式與分項式規範

| 型態       | 本章定義                     |
| ---------- | ---------------------------- |
| **涵括式** | 以一般性法律規範個人資料     |
| **分項式** | 依特定領域或資料類型分別立法 |

## 2.2 告知、同意與資料主體權利

- 本章的告知清單圍繞：**誰蒐集、為什麼蒐集、什麼資料、如何使用、提供給誰、如何行使權利**。
- 本章列出的個人權利：**查詢／閱覽、製給複製本、補充／更正、停止處理及利用、刪除**。

## 2.3 動態同意與治理

| 概念         | 重點                                               |
| ------------ | -------------------------------------------------- |
| **知情同意** | 充分理解之後作出選擇                               |
| **動態同意** | 持續通知、表達或調整意願，保存存取與選擇紀錄       |
| **專責治理** | 有明確人員、資源與程序維護隱私，處理跨部門需求衝突 |

# 3. 資料釋出與再識別風險

## 3.1 去除直接識別資訊仍有風險

- 直接識別欄位：如姓名、身分證號碼、病歷號碼。
- 去識別處理可降低風險，但仍須考慮其他資料的連結與推論。

## 3.2 CellSecu 的處理流程

```text
查詢／資料連結需求
  → 產生原始結果
  → Filter：移除直接識別欄位
  → Confidentiality test：依管理者規範測試
  → 若未符合，Generalize：降低精細度
  → 產生可釋出的結果
  → 保存稽核紀錄
```

- 管理者設定隱私策略；稽核中心保存操作與結果相關紀錄。
- ==保護強度與資料效用存在取捨==：太精細可能增加風險，太粗略可能失去分析用途。

# 4. 受控資料中心

| 作法                       | 能解決什麼                     | 仍須注意什麼                 |
| -------------------------- | ------------------------------ | ---------------------------- |
| **限制資料帶出**           | 減少原始資料散布               | 輸出結果本身仍可能洩漏資訊   |
| **在受控環境分析**         | 集中管理帳號、程式及存取       | 建置與使用成本               |
| **遠端送程式執行**         | 降低親赴中心的不便             | 程式隔離、執行安全與輸出審查 |
| **稽核多次查詢**           | 發現利用多次結果反推個人的行為 | 不能只看單次查詢是否安全     |
| **提供模擬／合成資料練習** | 讓使用者先測試程式             | 測試資料的代表性及釋出風險   |

- **沙箱**保護執行環境，**輸出審查**保護離開環境的資訊，兩者目的不同。

# 5. 多資料庫合作與安全多方計算

- **MPC** 讓多個單位共同計算某個結果，依其安全模型限制彼此取得對方的私密輸入。
- 本章強調：==輸出本身允許透露的資訊，與計算過程額外洩漏的資訊，要分開看==。

# 6. 基因資料與連結風險

- 生物資料庫的基因資料可能與公開家譜、姓氏或其他背景資訊串連。
- 本章以 **Y-STR 與家譜資料推論姓氏**為例，提醒識別風險可能來自外部資訊。
- 本章引用 **CNS 29100 隱私框架**，重點在完整治理與風險評估，不能只靠一個去識別步驟。

# 7. 差分隱私

## 核心概念

- 比較只差一筆資料的**相近資料庫**；不論某人的資料是否在其中，回覆機制的行為都「幾乎」一樣。
- 「幾乎」的程度可用參數調整，代表隱私保護強度。

# 8. 健保資料二次利用與憲法判決

## 8.1 什麼是二次利用？

- 健保為辦理保險業務蒐集資料，之後供原始目的以外的統計或研究使用，屬本章討論的二次利用。
- 本章指出缺乏事前表達同意及退出機制，引發資料二次利用的隱私爭議。

## 8.2 2022 年判決背景

- **2022 年 8 月 12 日，111 年憲判字第 13 號「健保資料庫案」**。
- 本章整理的重點：相關研究利用規定並非全面違憲；但獨立監督、組織程序與請求停止利用等規範不足，須補正。
- **補正期限：判決宣示日起三年內**修正或制定相關法律。
- **退出機制（opt-out）**：讓個人能表達停止資料二次利用的意願。

# 技術比較與考前速記

| 方法             | 主要保護對象                   | 仍需注意                     |
| ---------------- | ------------------------------ | ---------------------------- |
| 刪除直接識別欄位 | 明顯身分資訊                   | 間接識別與外部資料連結       |
| 概化             | 資料過度精細造成的識別性       | 分析精度下降                 |
| 受控資料中心     | 原始資料的存取與流出           | 多次查詢及輸出洩漏           |
| 沙箱             | 程式執行範圍                   | 不能取代輸出審查             |
| MPC              | 合作計算的私密輸入             | 信任模型、輸出本身的推論     |
| 差分隱私         | 有／無某筆資料時，回覆幾乎一致 | 隱私保護強度與分析效用的平衡 |
