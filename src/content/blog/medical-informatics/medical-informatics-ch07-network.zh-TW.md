> [!IMPORTANT]
> **重要考點**
>
> - 最常考的字串：==平均修復時間／停機時間（MTTR）→ 回復能力或穩定度==。
> - 可靠度、容量、延遲分開：**可靠度看可用及復原；容量看資料率；延遲看花多久**。
> - **ATM＝Asynchronous Transfer Mode，連線導向，固定 53 bytes cell**。
> - **Gigabit Ethernet → 1,000 Mbps、IEEE 802.3z**；不要換成 WLAN 的 802.11。
> - **SNMP：GET 讀取、SET 設定、Polling 輪詢、Trap 主動通知**。

# 1. 為什麼醫院需要網路規劃？

- **PACS 大型影像**可能需要大量傳輸容量，**互動式醫令**重視回應時間，**連續性照護服務**重視可用性。

# 2. 以服務為導向的設計

## 2.1 使用者需求的七個面向

| 面向                         | 應了解的問題                                         |
| ---------------------------- | ---------------------------------------------------- |
| **回應 Response**            | 查詢或資料取回要等多久？大量傳檔與互動查詢的期待不同 |
| **可用性 Availability**      | 需要哪些時段可用？中斷多久可接受？                   |
| **品質 Quality**             | 使用者端的語音、影像與操作品質是否符合需要？         |
| **可適應性 Adaptability**    | 新增應用、使用者與設備時能否調整？                   |
| **安全性 Security**          | 如何驗證身分、授權、保護傳輸與管理存取？             |
| **負載能力**                 | 尖峰同時使用時，容量是否足夠？                       |
| **成長期望 Expected growth** | 未來人數、資料量與服務會如何增加？                   |

- 本章另列以使用者為中心的四個設計階段：**需求分析 → 設計概念發展 → 雛型設計 → 設計評估**。

## 2.2 三大效能度量

| 度量                   | 常見指標                                   | 判斷方式                             |
| ---------------------- | ------------------------------------------ | ------------------------------------ |
| **可靠度 Reliability** | 可用率、MTBF、MTBSO、MTTR、BER、封包遺失率 | 故障是否少、恢復是否快、傳輸是否可靠 |
| **容量 Capacity**      | 尖峰、持續與最小資料率；實際傳輸量         | 能承受多少工作量                     |
| **延遲 Delay**         | 單向延遲、RTT、端到端回應時間              | 一次操作多久完成                     |

- **Ping** 可觀察往返時間及封包遺失。
- MTBF 通常越大越好，MTTR 通常越小越好。

| 可靠度面向       | 對應關鍵字                               |
| ---------------- | ---------------------------------------- |
| 可利用率         | 正常運作時間與當機時間的百分比           |
| 回復能力或穩定度 | MTBF、MTBSO、平均修復時間／停機時間 MTTR |
| 傳輸錯誤及遺失   | BER、細胞遺失、資料框或封包遺失          |

## 2.3 延遲來源

| 類型         | 核心意義                   |
| ------------ | -------------------------- |
| **傳播延遲** | 訊號經傳輸媒介前進所需時間 |
| **傳送延遲** | 傳送資料所需時間           |
| **處理延遲** | 設備處理資料所需時間       |

# 3. 使用者需求分析流程

1. **收集需求**：使用者對象、位置、人數、作業、應用與預算。
2. **設計度量**：選可靠度、容量與延遲指標，定義測法。
3. **描述使用模型**：人數、使用頻率、每次 session 時間及預期成長。
4. **描述應用行為**：每次資料量、頻率、方向、持續時間及一對一／多點傳輸。
5. **設定門檻**：何時達標、何時告警，並說明尖峰與正常條件。
6. **區分服務需求**：結合應用分布圖及服務規範，安排資源。

# 4. 乙太網路交換器

| 轉送方式                         | 何時開始轉送             | 主要取捨                             |
| -------------------------------- | ------------------------ | ------------------------------------ |
| **Store-and-forward 儲存後轉送** | 收到完整訊框並檢查後     | 可先檢查 CRC，需等待完整訊框         |
| **Cut-through 穿透式**           | 讀到足以轉送的目的資訊後 | 降低轉送等待，可能已轉送有錯誤的訊框 |

# 5. ATM 與 Gigabit Ethernet

| 技術                 | 本章考點                                                                     |
| -------------------- | ---------------------------------------------------------------------------- |
| **ATM**              | 連線導向；固定 **53 bytes** 的 cell；具有 QoS 設計；目標整合語音、影像及資料 |
| **ATM 與既有 LAN**   | 本章介紹 LANE、MPOA 等銜接方式，並討論轉換帶來的成本及延遲                   |
| **Gigabit Ethernet** | **1,000 Mbps＝1 Gbps**；本章著重 IEEE 802.3z 與 SX／LX 光纖介面              |
| **全雙工與半雙工**   | 兩者行為須分清楚；本章的 CSMA/CD 與碰撞敘述有早期共享媒介脈絡                |

# 6. 無線區域網路與藍牙

## 6.1 無線區域網路演進

| 標準            | 本章範圍內的頻帶與標稱資料率              | 複習重點                                 |
| --------------- | ----------------------------------------- | ---------------------------------------- |
| **原始 802.11** | 紅外線、FHSS、DSSS 等早期實體層；1–2 Mbps | 早期 WLAN 基礎                           |
| **802.11b**     | 2.4 GHz，最高 11 Mbps                     | 舊世代 2.4 GHz WLAN                      |
| **802.11a**     | 5 GHz，最高 54 Mbps                       | 與 b 的頻帶不同                          |
| **802.11g**     | 2.4 GHz，最高 54 Mbps                     | 可與 b 的系統配合；不代表變成 5 GHz 的 a |

## 6.2 三類應用

| 應用             | 核心功能                       | 醫院情境           |
| ---------------- | ------------------------------ | ------------------ |
| 接入既有有線網路 | 無線端透過接入設備連到院內網路 | 行動工作站         |
| **漫遊 Roaming** | 裝置移動時在接入設備間切換     | 查房推車跨病房移動 |
| 跨建築物橋接     | 以無線鏈路銜接兩個網段         | 建築物之間的連結   |

## 6.3 無線安全的三個面向

| 面向                       | 意義                 | 本章內容                         |
| -------------------------- | -------------------- | -------------------------------- |
| **認證 Authentication**    | 驗證身分或持有的憑證 | 本章介紹早期開放／共享金鑰等模式 |
| **機密性 Confidentiality** | 防止未授權者閱讀內容 | 本章介紹 WEP，須視為歷史機制     |
| **完整性 Integrity**       | 檢查資料傳輸有無錯誤 | CRC 檢查                         |

## 6.4 藍牙

- 本章考點：**2.4 GHz、跳頻、低功率、裝置間短距離連結**。

# 7. 網路布線

## 7.1 布線規劃的重要性

- 本章介紹 **PDS** 及 **TIA／EIA-568** 的發展脈絡，以整合語音、資料、影像等需求。
- 本章用「布線占成本約 5%、造成約 70% 當機」說明布線規劃的重要性。

## 7.2 光纖的優點與限制

| 優點                           | 對醫院網路的意義               |
| ------------------------------ | ------------------------------ |
| 頻寬與長距離傳輸能力           | 適合骨幹、大型影像與跨區連結   |
| 體積小、重量輕                 | 改善管道與空間利用             |
| 玻璃介質的電氣隔離、抗電磁干擾 | 適合需降低電氣與干擾影響的環境 |
| 衰減低                         | 有利較長距離傳輸與減少中繼需求 |

## 7.3 整合式布線與傳統布線

| 傳統專用布線                          | 整合式布線                           |
| ------------------------------------- | ------------------------------------ |
| 先求接通，較依賴專用線材與接頭        | 重視前瞻規劃與通用元件               |
| 使用彈性較低、維護較繁複              | 較易調整用途及維護                   |
| 本章例子：初建 100 萬、每年維護 20 萬 | 本章例子：初建 120 萬、每年維護 3 萬 |

## 7.4 線材類別、頻率與資料率

- 本章列 Cat 3：16 MHz、Cat 4：20 MHz、Cat 5：100 MHz；另出現 **「6E：200 MHz」「7F：600 MHz」**等用字。
- **MHz 是頻率範圍指標，Mbps／Gbps 是資料率，不可直接互換。**

# 8. SNMP、MIB 與 RMON

## 8.1 管理架構的四個部分

| 部分                | 工作                                       |
| ------------------- | ------------------------------------------ |
| **管理端 Manager**  | 提供管理介面，監看、查詢、控制與彙整資料   |
| **被管理端／Agent** | 設備上的管理功能，提供狀態與回應操作       |
| **MIB**             | 定義可管理物件及其結構；設備提供相應物件值 |
| **通訊協定 SNMP**   | 在管理端與 Agent 之間交換管理訊息          |

| 操作／方式       | 意義                               |
| ---------------- | ---------------------------------- |
| **GET**          | 管理端讀取值                       |
| **SET**          | 管理端在權限允許時設定值           |
| **Polling 輪詢** | 管理端定期主動詢問設備             |
| **Trap**         | Agent 主動發出通知；與輪詢方向不同 |

- 本章提到 **SNMPv3** 的安全功能。

## 8.2 RMON 的定位

- 在監測端就地收集、統計與分析資料，再將結果提供管理端，減輕逐一輪詢及集中分析的負擔。
- RMON 可配合 SNMP 進行遠端網路監測。

## 8.3 Intranet

- 以 Internet／WWW 技術處理與傳遞組織內部資訊，形成企業內部網路。
